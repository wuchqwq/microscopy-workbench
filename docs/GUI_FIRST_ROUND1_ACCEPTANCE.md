## Observed starting problems and chosen fixes

The original #48 GUI was used against its real Panel/MCP/Python stack before
changes. Actual source/ROI/save/selection gestures and screenshots were retained.

1. Saving ROI attention required opening the generic properties form and gave no
   persistent observation list. The selection-only **AI 交接** message said the
   choice was handed off but supplied no clear next step. Added a visible saved
   observation/reason surface and honest copyable Agent continuation. Internal
   IDs are generated/attached; no fabricated automatic wake. Empty tables no
   longer occupy half the starting canvas.
2. Actual generic comparison evidence had no same-Panel attachment channel;
   #48 correctly kept its PNG in MCP rather than passing a structure ID as an
   image. Added a finite, provider-admitted evidence card and explicit original
   observation/FFT links, with stale/unknown/ambiguity/recovery distinctions.
3. Actual display-settings access was obscured by the new evidence sidebar.
   Settings now closes that sidebar; returning retains the observation reason
   and display draft. A real-browser check and actual-handler regression cover it.
   Independent final review also found a pending-save typing race: the reason
   input alone is now disabled while busy/gesturing so an acknowledgement cannot
   clear newer text. Pan/zoom/observation controls are not globally disabled.

This is not a general frontend rewrite, second science engine or new workflow
platform. Broad history navigation remains the existing implementation; these
changes preserve the specific saved observation/evidence references needed
for this task.

## Retained failures found during this round

- The first new save entry assumed `object.annotations` existed. Real first-frame
  data omitted it, so an error occurred before dispatch; the typed reason remained
  a draft. Fixed with bounded empty-array handling and a targeted actual-handler
  regression. The corrected browser task was restarted explicitly; no unknown
  scientific operation was replayed.
- An independent controlled counterexample found same-frame/same-calibration
  **third FFT** could be mislabeled current for a two-FFT comparison. It now
  refuses fresh attachment and marks an existing card `needs_review`; valid A/B
  FFTs stay current. Failure/fixed probe records remain separate.
- Backend test fixtures initially omitted ancestry and were correctly refused by
  the frame guard; fixtures were corrected, not scientific conditions relaxed.
- New-tool preflight failure originally had no durable request record. The exact
  same ID could later acquire a different outcome. New attachment intents are
  now fsynced before provider inspection, deterministic failure stays failed,
  and unknown dispatch only queries the original outcome. Old Panel tools keep
  their original contracts.
- Independent probes found two ways a new comparison could omit known edited
  evidence: replacing its FFT, or removing a bare point without a measured-ID
  binding. Both now refuse rather than clear pending state or guess identities.
  The original FAIL and fixed PASS artifact hashes are retained in the public
  [guard summary](validation/gui-first/guard-controls.json).

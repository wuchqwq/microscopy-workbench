## New, explicit scientific contracts

`image_domain_map(neighbor_policy:"support_contact_v1")` opts a newly created
map into same-scale overlap and positive-shared-edge adjacency. Edge records
retain support relation, overlap area/shared-edge length and unknown gap
evidence. Corner-only contact, positive gaps, different scales and unusable
measurements are distinct. The omitted/default `legacy_cardinal_v1` path keeps
historical map reconstruction unchanged. A wider support graph is not evidence
of physical boundary localization or material identity.

Eligible field/map/proposal, `image_info` and `image_result` calls accept
`response_detail:"compact"`. The response is explicitly non-authoritative and
retains scientific object identity, manifest hash, settings, quality, counts,
references, executable proposed actions and budgets/stops. It is a delivery
projection of the ordinary validated record; the flag does not become a new
scientific journal parameter or change original-request identity.

Use `image_evidence(object_id, manifest_sha256, section, offset, limit)` for
selected exact rows. The limit is at most eight, with a bounded response size.
Samples, actions, neighbors, domains, boundary bands and increment history remain
available without feeding the full recursive workspace into every Agent turn.
Full receipts and scientific export remain available. Concision does not permit
skipping source/parameter/hash checks or treating a summary as a new authority.

## Small public input and GUI relay

The source is a new 96×96 float32 TIFF generated from the same analytic A/B
reciprocal vectors used by F4, with a synthetic X=32 interface. No physical scale
is supplied. One 64-pixel coarse observation plus two 32-pixel observations at
`[0,0,32,32]` and `[32,8,64,40]` cost exactly three FFTs /6,144 FFT pixels. The
fine supports have a 24-pixel positive shared edge despite offset centers.
This geometry was selected to exercise the general adjacency contract, not to
repair or retune the frozen shifted-strip experiment.

In the retained real-GUI path, the Panel opens the saved source-bound map. A
researcher opens one saved FFT, moves an existing peak and saves/remeasures it.
The relay consumes that
actual measurement and its annotation/scientific coordinates, replaces only the
complete measurement list of its stable `observation_key`, then saves a new
field/map and CAS current context. It must create no FFT, retain the old
measurement and legacy map, and preserve source TIFF, extracted source pixels,
ROI arrays and all three complex spectrum hashes. Label-only movement is not a
scientific correction.

## Reproduction entrypoint

Use the independent science Python environment and a new evidence directory:

```powershell
$env:MICROSCOPY_PYTHON = 'C:/path/to/science-env/Scripts/python.exe'
$env:MICROSCOPY_SMOKE_OUTPUT = 'C:/path/to/new-closeout-evidence'
$env:MICROSCOPY_CLOSEOUT_STAGE = 'prepare'
node dist/tools/smoke_active_closeout.mjs
```

The private receipt supplies the actual MCP-returned Panel URL and exact saved
target. Open only that verified local Panel, perform the peak correction and
wait for its saved measurement. Then run the same entrypoint with
`MICROSCOPY_CLOSEOUT_STAGE=resume`. Resume refuses an unchanged anchor or missing
saved measurement; it never fabricates the GUI result or replays an unknown
operation. A started resume is not silently rerun. Query its original request
receipts if it stops unexpectedly.

In this run, Computer Use stopped because it could not determine the current
browser URL on Windows with enough confidence to enforce policy. The GUI
gesture path remains unqualified. The separately requested `mcp-revise` stage
uses only formal `image_annotate` and `image_remeasure`: a predeclared +0.003
cycles/pixel synthetic anchor revision, followed by the same scientific relay.
It does not post Panel UI actions, fabricate `last_operation`, simulate a mouse
gesture or satisfy the browser gate. The real-GUI `resume` path is retained for
a future safely controlled human session.

The independent numerical stage is explicit:

```powershell
$env:MICROSCOPY_CLOSEOUT_STAGE = 'mcp-revise'
node dist/tools/smoke_active_closeout.mjs
```

The prepare/resume logs measure MCP result-body bytes and wall elapsed time;
they are not packet sizes or separate internal compute/validation phases.
Root-owned controlled comparisons report those distinctions separately.

## Reusable continuation

A fresh compatible Agent can be asked:

> Continue the named analysis `<task-name>` after the saved peak correction.
> Inspect compact current evidence and expand only the needed observations or
> neighbors. Within five total windows and 8,192 FFT pixels, retain exploration,
> choose at most two further 32-pixel actions, update the explicit support-contact
> map and current references, then stop with the recorded rule. Preserve the
> prior three spectra and source. Save request IDs before writes, query unknown
> outcomes, and leave physical scale/material interpretation unknown when
> unsupported. Return the result to the existing Panel without replacing drafts.

These numbers apply to this three-window fixture, not universal defaults. Named
AnalysisContext, provider records and original IDs support reconnecting without
reconstructing an FFT or requiring a prior developer chat. Other image tools
remain directly callable without this analysis loop.

# 同一源帧的多 ROI 图像窗口

本轮采用 TypeScript `.mts`，沿用既有 Panel、科学工作区和正式构建，不引入 React。
同一源帧的来源图、局部显示和 FFT 可保留为多个窗口，便于对照 A/B 两处区域。
窗口只是已保存对象的展示引用；provider journal 仍是科学记录的权威。

## 第一阶段：多窗口展示

窗口集合最多五项，足以容纳来源图、两张局部图和两张 FFT。主动“查看选区”或 FFT
产生新保存显示时增加窗口；同一科学网格上的峰、标注和显示修订更新原活动窗口。
标题、布局、平铺和只读缩放不构成科学计算。关闭只移除窗口，不删除对象、测量或历史。
达到上限时保留已完成结果等待查看，研究者关闭不需要的只读窗口后再接纳，不自动挤走旧图。

始终只有一个当前科学编辑器，其他窗口只读。第一阶段沿用 P3“返回空间观察”使来源图
成为当前图，随后可以继续选择另一 ROI。活动窗口不可直接关闭；先通过受保护返回路径
使它变成只读窗口，才可关闭。不同源帧不放在同一集合比较，原记录仍在工作区中保留。

宽屏支持拖动标题、调整窗口尺寸及平铺。点击窗口内容或边框可置顶，只改变遮挡顺序，
不切换科学编辑目标。窄屏优先显示当前编辑图，其他窗口的保存引用
继续保留。观察、属性和结果按需打开。全局待接纳、保存核对和未知请求提示不属于某一
子窗口，不能通过关窗隐藏。

待查看结果存在时，仍可保存当前同网格的观察或理由修订；保存与两次读回核对完成后，
交接仍须等待该结果被处理。新图计算和导航在原待查看引用解决前受阻，不重复派发 FFT。

## 来源和科学语义

每个 FFT 记录准确输入保存视图、源帧、原 FFT 身份和实际整数处理窗口。同帧、同尺寸
或看起来相似都不能证明两个 FFT 来自同一选区。当前交互框与 FFT 处理窗口分别表达。
改选区不自动重算，也不把旧 FFT 重新标成新选区的结果。

源图和 FFT 的当前显示修订与原输入身份分别保留。历史来源关系与当前标定一致性不同：
后续改标定不改写原 FFT 输入，各图按自己的标定版本解释；不因此改变 P3 返回旧来源
的行为。并排展示不确认峰可靠性、应变或物相，三层结果语义保持独立。

只读窗口读取已保存 PNG 和 metadata，不触发 image_preview 或 FFT。资产仍核对准确
对象、同源帧、面板映射、路径和 PNG 哈希/字节预算。失败时明确该窗口不可用，不用
当前图或其他最近对象冒充。MCP 顶层 object、selection、edit_state 只描述活动图；
窗口摘要里的其他引用不是第二个活动科学输入。

## 状态与恢复

PanelState 的可选 window_collection 是有版本、数量上限的展示状态。图像载荷单独按
当前集合中的窗口身份读取，不把五幅 PNG 放进每次状态轮询。布局或关闭操作核对准确
当前对象和集合版本，保留科学选区、草稿、last_operation 和原请求。

owned checkpoint 只增加已有对象的引用与布局，旧档缺字段按既有单图恢复。恢复读取
保存资产；某个只读窗口失效不能清掉当前编辑记录。关闭浏览器不等于 helper 已正常退出，
正式 CLI 中断资格需独立验证。

本阶段仅对受支持活动图恢复窗口集合。不支持的多面板图可暂时保留旧只读引用，但停在
这类图上冷重开会保守退回原单图恢复；不把它宣称为完整窗口历史恢复，科学对象仍保留。

## 后续阶段

第二阶段加入有服务端双重检查的“编辑此图”，保存两域的有限相机、合法临时选区和
选中标注。仅有一份活动草稿及编辑租约，不在隐藏窗口另建待保存队列。服务端已接纳
而浏览器尚未显示时须标记“切换接续中”，旧画面不能进行科学写入或正式交接。

第三阶段增加后来保存的观察与既有结果的引用关联，并提供经过验证的只读来源观察
上下文，使 FFT 活动状态下的 Agent 交接可以明确完成。当前已有交接合同不因出现
窗口摘要而自动升级；第一阶段仍从来源空间观察交接。

GUI 文件打开和完整提案拒绝另立有界任务；多原图、多帧比较不在本轮已授权范围。

## 验证边界

按实际改动运行窗口/Panel/UI、合同双方与 owned 恢复检查；科学边界只补必要正式 MCP。
Windows 使用公开合成图验证 A/B ROI、两份 FFT、拖动/调整/关闭、重开和旧测量引用。
保留首次失败，未执行的手势明确 NOT_TESTED，不宣称真实样品或完整 GUI 验收通过。

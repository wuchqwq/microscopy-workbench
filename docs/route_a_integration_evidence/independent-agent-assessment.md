This is a read-only assessment, not another production change. It evaluates actual MCP operations, returned image blocks, saved evidence and final reasoning, not exit code or wording alone. Assessment sequence: read the four actual event streams and finals; inspect the saved scientific objects and image previews; then read the separate assessor truth file to compute descriptive errors. The tested Agents did not receive the assessor truth. Their launch records supplied public Skills, a finite tool allowlist and a task; they did not automatically discover Skills. ## Four categories, kept separate

### 1. Implementation errors and operational gaps

The preserved **r29-first** run encountered a genuine Panel interaction-gate defect before the successful repeat: actual `image_panel_current` returned `interaction_gate.status=blocked`, `reasons=[operation_unresolved]` despite no user draft or active gesture. The Agent stopped instead of circumventing the gate. This is a retained failed run, **not** a successful end-to-end analysis; the root work records the local fix and regression. `r29-fixed` must not replace or erase it.

No new FFT/coordinate/data-integrity bug was found in the four successful runs. A separate operational completeness gap remains: every saved rectangle in these four runs has `annotation_id=null`. Actual `roi_handoff.saved_rectangles` therefore reports `usable=false`, reason “Saved rectangle has no bounded annotation identity.” The explicit ROI is still preserved in the FFT source records, and r29, r08 and r36 explicitly acknowledge the handoff limit. The r42 final does not mention this limitation even though its final Panel response exposes it. However, these runs do **not** prove a complete stable saved-ROI continuation path. This is an Agent/tool-contract integration issue, not a numerical-frequency bug; a future explicit edit/revision with an annotation ID should be tested without rewriting these historical objects.

One minor report discrepancy: r29-fixed correctly counts 14 top-level calls but its counting explanation says four `Panel current` calls; the actual stream contains **three**. The scientific action/result references are otherwise consistent. Treat the raw event list as authoritative; do not silently correct the original final.

### 2. Measurement uncertainty

Observed weak-signal localization variation, an extra random maximum in r42, and r08's window-dependent/blended maximum belong here. The current tools did not evaluate calibrated significance, localization intervals or close-component resolution. The Agents retained these as unknown and did not equate their local amplitude ratio with SNR. Their single-window contrast is a performed sensitivity observation, while the saved individual-object `parameter_sensitivity=not_assessed` remains correct for that object's own operation. The Agent note can describe a cross-object comparison without retroactively changing a prior object's semantics.

### 3. Method limitations

Finite support/window response, merging of close Fourier components and peak-list truncation constrain what the basic detector supports. Two views of one source do not supply independent experiments. A failed multi-direction feature would not invalidate an existing one-direction conditional period; these four Agents did not unnecessarily require a whole-image structure field or a full multistage pipeline. None of these runs is a validation of GPA, topology, scattering intensity, detector-specific noise or a material image-formation model.

### 4. Physical non-identifiability

Without calibration/material/imaging information, projected lattice fringes, imaging/process modulation and some other periodic textures can remain compatible with the same observed image period. A finite same-image processing contrast cannot uniquely settle those origins. The four Agents retain that ambiguity; none outputs a unique phase, twin, defect, 3D structure or calibrated candidate probability. The two explicit crystal candidates sharing a projection are **not covered by these first four runs**; the later dedicated case is assessed separately.

## Boundaries of the positive conclusion

These runs provide actual evidence that a source-blind Agent can select ROI/processing/peak actions from returned images and metadata, save traceable pixel-domain measurements, record a reasoned working preference, and preserve unknown measurement/physical qualifications. This is stronger than a static snapshot answer and narrower than scientific certification.

It is not yet evidence of: browser gesture correctness, automatic Skill discovery, handling an actually unknown side-effect request, successful saved-ROI handoff from these ID-less annotations, acceptance of a human edit/stale-result rejection in the initial r36 run, or a unique structural comparison. Those are explicitly **NOT_TESTED** in this report and must be credited only by the separate integration/currentness cases. No test here requires the Agent to guess a hidden generator or to produce a physical answer from insufficient observations.

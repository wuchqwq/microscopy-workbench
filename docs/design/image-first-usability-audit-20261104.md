# 图像优先 UI：独立可用性审查

2026-11-04。结论：现有选择、平移、ROI 和 FFT 已提供基本操作入口；主要学习负担来自**状态像按钮、同名控件含义不同、结果入口分散，以及长期显示的技术说明**。应先减少这些歧义，不必重做窗口管理器。

范围：查看用户提供的截图，核对本分支 [界面结构](../../ui/image-panel/index.html)、[交互状态](../../ui/image-panel/app.mts)、[视图历史](../../ui/image-panel/user-workflow.mts)、[保存控件](../../ui/image-panel/workspace-controls.mts)、[结果区](../../ui/image-panel/measurement-workspace.mts) 和 [样式](../../ui/image-panel/style.css)。截图、像素及样品信息不随报告上传，也不认定该图是公开合成输入。**原生操作／人类可用性 NOT_TESTED**；本报告是截图与代码审查，不能据此证明点击命中或窗口尺寸适配通过。

## 优先处理的四项

| 问题与证据 | 最小建议 | 性质／验证边界 |
| --- | --- | --- |
| **“保存视图”看起来像保存按钮。** 截图可见其边框、底色和按钮相似；代码确认 `#view-current` 是不可点击的 `span`，内容来自 `SavedViewHistory.remember()` 的默认 role“保存视图”。它既不是保存动作，也不是明确保存状态。截图裁掉了总 header；真实 `#workspace-save` 和独立保存状态存在，不能说软件没有保存入口。 | 将此位置改为普通图像类型／名称，如“空间图”，去掉按钮外观。工作区保存状态只由现有 owner/CAS／读回合同驱动；不能把底层已记录版本叫作用户已保存。 | **局部呈现误导，可轻修。** 不改保存行为；需确认文字不会把裁剪历史图冒称完整原图。 |
| **“接下来做什么”不够明确，同名“测量”含义不同。** 截图中已有框但“当前 ROI：未选择”，这是选择状态，不能认定 ROI 丢失。`showDraft()` 在无选择时统一提示圈区域／点峰；左栏“测量”切换画线工具，图下“测量”执行测量，实际是两个阶段。 | 未选中时提示“点击已有 ROI；按 R 添加”。有选择时只给对应动作，例如“ROI 2 → FFT”；线工具名改“测量线”，动作名“测量长度”，频域则“测量周期”。框、当前选中控制点和只读 FFT 支持区继续明确区分。 | **局部提示／命名可轻修。** 保留首次激活只激活、重叠消歧及 Delete 保护；实际命中、重叠和读屏效果待操作。 |
| **“比较”和“结果”需要先猜入口分类。** 代码确认“原图与 FFT 对照”在“窗口”菜单，也可在属性关联中找到；“ROI 对照结果”在“结果与历史”，数值测量却在底部“数据结果”。顶部“结果”并不等于底部“结果”。 | 当前 FFT 的图下动作中优先提供现有“原图与 FFT 对照”，复用同一 handler；空间 ROI 仍优先 FFT，不新增常驻工具栏。将顶部菜单明确为“分析历史”，底部统一承担数值结果；已有报告保留准确来源与明确采用边界。 | **入口层级需确认。** 仅显式点击才平铺／Fit；不能因选择或轮询重置相机、采用结果或重算。 |
| **底部重复承担操作说明、保存说明和显示偏好诊断。** 截图可见窗内说明、当前 ROI 行、双行状态、折叠结果行；其中长期提示面板开合恢复细节，会抢占日常分析注意力。底部“历史 4 条·已筛选隐藏”是正确区分，仍要求用户自己寻找过滤开关。 | 正常状态保留简短对象／选区与工作区保存状态；恢复偏好等技术细节移入现有诊断。阻断错误、未决请求和保存失败仍持续可见并有恢复动作。折叠结果摘要可提供“显示历史结果”这一明确的纯查看动作。 | **信息精简可小步实施。** 不隐藏风险、不清空草稿；主动展开结果后不得被后台折叠。193% 本身不是缩放错误。 |

## 最小动作表

以下仅比较代码可数的显式入口，不包含网络等待、激活检查或研究者判断时间。

| 已处于的状态 | 当前入口 | 建议入口／影响 |
| --- | --- | --- |
| 空间图已激活，选择非重叠、可编辑的已有 ROI | 点击 ROI → FFT：2 个动作 | 保持 2 个动作，改清楚提示，不额外要求保存观察或填理由。 |
| FFT 已激活、来源合格、窗口容量足够，菜单关闭 | 窗口 → 原图与 FFT 对照：2 次点击 | 当前图下“原图与 FFT 对照”：1 次点击；沿用全部资格／草稿保护。 |
| 结果区收起且历史被过滤 | 展开数据结果 → 勾选包含历史版本：2 次点击 | 摘要“显示历史结果”：1 次明确查看动作；不改变采用或保存状态。 |
| 工作编辑已就绪 | Ctrl+S：1 次动作 | 保持 1 次；读回成功后才显示已保存。 |

信息层级草案：**图像与当前对象动作**为第一层；**属性／观察、数值结果**按选择展开；**分析历史、Agent、显示与高级设置**按需进入。来源证明、请求 ID、资格 JSON 继续放高级诊断，日常操作者不应先学这些概念才能画 ROI、FFT 和保存。

## 两项建议确认的决定

1. 是否把当前 FFT 的“原图与 FFT 对照”作为主要上下文动作，并把顶部“结果与历史”明确称为“分析历史”？这改变入口层级，需确认后实施。
2. 是否采用单一简短的常态状态区，技术恢复说明移入诊断；错误、未知结果与恢复动作保留醒目展示？先给低保真预览再改布局，不先删除保护信息。

不新增科学功能、不更换框架、不重做历史或窗口系统。上述四项不应自动扩大成成熟软件全部功能缺口清单。本报告未改产品源码，未执行新测试或操作用户窗口。

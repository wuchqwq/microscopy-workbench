# 来源链边界与旧 null 保存点：最小合同

关联 #108。来源资格、科学执行完成、执行输入证据可复用，是三个不同的判断；找到 frame 不代表所有后续消费者均已通过。

## 本轮实施的局部修复

Panel 原循环允许根对象加 64 次祖先读取，但出口漏评估已经读到的第 65 条终端记录。现在先评估读到的对象，再决定是否允许下一次读取。原 64 次祖先读取预算不变，第 66 条不会被悄悄读取。普通与 provider 捆绑路径共享解析语义，分别表达 found、预算耗尽、缺失、损坏、环、无法支持及读取失败。原 provider 错误保留原错误对象、状态与原因。

支持既有 `include_frame_ancestry` 的 provider 可返回已逐项核对 payload、路径及哈希的有界投影。恢复尝试内复用普通和捆绑读取的两个独立变体；提交前使用最初读取闭包重新取得完整捆绑结果。缓存不跨尝试、不跨请求存活，不以普通根对象读取代替祖先重新校验；旧 provider 保留原读取路径与预算。

## 旧保存点保持原样

仅对准确可信旧快照满足以下条件时兼容：原 frame 明确为 null，窗口记录全空、没有待接纳结果和未知科学执行；原对象是单一空间视图，重新验证完整 65 条记录确实找到 frame。这是对旧循环出口的窄兼容，短链 null、别的 frame、非空旧窗口及其它任意 null 不会通配通过。

启动时继续呈现旧 frame=null，提供“重新核对来源”。显式操作冻结对象、草稿、状态、窗口、工作版本及原保存点；有编辑、手势、未决保存、恢复副本或原请求时拒绝提交。沿同一旧对象重新核对现有资产及来源，并在所有异步读取后重新检查权限、版本与原引用，才更新新的工作 frame 和来源窗口。操作不创建预览、FFT 或新的科学数组；操作请求和结果记录在已有 Panel journal，可查询原操作，未知结果不自动重放。

Ctrl+S 创建新的明确保存点，旧保存点和 origin 不变。若研究者明确“不保存”，仅对同一准确旧保存点走相同的 deferred-null 校验，恢复原 null 和待核对状态；普通保存与其它恢复保持严格 frame 比较。

## 本轮明确没有消除的深历史限制

真实 65 条输入已经可以执行 FFT、恢复已存在 FFT、准确返回原输入并保存重开；但其冻结执行输入的独立科学依赖图仍因 64 节点预算而记为 `qualification=unavailable`。原计算确已完成，不能说“没有结果”，也不能让 Agent 把未通过的来源证据当作可复用资格。CLI 还有独立读取预算。66／80 条来源链仍明确预算耗尽，不通过修改常数、跳过祖先或更换原输入隐藏限制。

这需要统一来源证明策略，超出本轮循环局部错误。建议先审以下两种最小方案，不在本轮隐式实施：

| 方案 | 历史与安全语义 | 代价及取舍 |
| --- | --- | --- |
| A：分段核对完整来源，推荐先讨论 | 每段固定记录／字节／时间预算，绑定准确根对象和版本，明确继续读取；全部必需祖先验证完才授予资格。最后重新核对所有已用证明，保留缺失、损坏、环与中断状态。Panel、执行输入、CLI 使用同一口径。 | 复用现有对象读取，不需要第二套科学数据库；总耗时仍随历史增长。跨请求继续核对的冻结身份、累计上限及最终复核合同必须先确定。 |
| B：provider 生成版本化来源证明 | 对旧链完成全量验证后追加不可变证明，绑定准确对象、父证明、frame、数组／标定／配方及哈希；后续修订继承经过校验的证明。原历史不改。 | 后续读取较快，但引入持久来源证明及新的核心信任合同；迁移、失效与版本规则更多，须单独审查。 |

本轮保留原始反例及未通过的执行输入资格，不关闭深历史问题，也不将它解释为材料测量、应变或物相结论。

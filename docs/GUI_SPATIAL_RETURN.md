# FFT 返回保存空间观察

## 操作与身份

在一个已保存的空间视图选择矩形并执行“FFT”，Panel 保留该次转换前的准确空间
保存视图引用。频域导航条的“返回空间观察”使用现有视图接纳流程，打开该保存对象，
保留原 ROI、理由、标定和显示配方；不新建源帧预览，也不重算 FFT。
“← 返回 / 前进 →”仍是本浏览器会话的保存视图序列；本改动没有持久化完整历史。

“原图 / 全帧（新显示）”和“完整频谱”的原有含义不变。frame_identity 只说明原科学帧，
不证明输入属于实空间，也不能确定研究者希望返回哪一条观察。

## 保存与恢复合同

现有 owned checkpoint 新增可选的 `spatial_return_reference`：version=1、空间 view ID、
frame ID、原 FFT ID 和源像素支撑边界。它只保存有限引用，没有科学数组或另一套历史。

正常关闭后使用同一注册工作区重开，会通过 provider `image_info` 重新核对保存对象、
PNG SHA-256、单一空间面板、frame、原始 FFT 的标定依赖、身份及输入支撑范围。同帧的另一 ROI / FFT
不能借用此引用。合法的原 FFT 显示和峰修订仍可返回同一个保存空间视图。
旧 checkpoint 缺字段、错误身份或来源不明确时，当前 FFT 保留且入口不可用，不猜测目标。

结构合法的候选引用在临时读回失败后仍保留，但不具备返回资格；恢复来源后正常重开
会重新验证。坏结构不保留。资格变化更新操作性 revision，界面通过只读状态接续提示。

浏览器收到的 `spatial_return.status=ready` 只表示导航目标已核对，不是科学结果确认。
服务端 `return-spatial` 不接受任意目标参数，强制准确当前对象及 draft revision，并拒绝
草稿、手势、pending 和未确认的原请求。读回期间产生新草稿时，不切换当前图。
PNG 解码期间的新编辑可使 GUI 暂缓显示目标；此时只提示目标已读回、等待明确接纳，
不能把后端当前对象已切换冒充 GUI 已显示。

## 窄窗口中的既有面板

≤850 px 时仍使用现有观察 / 属性抽屉；面板覆盖范围按真实 `#viewport` 相对工作区
的位置更新，避开科研条、保存视图导航和底部选区操作。ResizeObserver 仅同步覆盖边界，
不改变相机、选区、草稿或科学对象；“适应画布”仍是研究者的显式操作。
窄屏 pending 提示进入文档流，导航和选区按钮允许换行，不再靠裁切隐藏操作。
展开的数据结果按其它区域占用后的剩余高度约束，内容在区内滚动；研究者设置的
高度值保留，宽屏或关闭结果区时解除该窄屏上限。
观察与属性面板互斥，关闭入口保留在可滚动面板的顶部，展开状态同步给辅助技术。
这是已有布局的局部可达性修复，没有加入可调宽度、另一套抽屉或完整布局改版。

“放弃草稿，查看保存结果”是明确撤回本地观察说明的操作。读取期间新写入的理由
仍保留，接纳失败或尚有待处理结果时不提示已经查看；未确认的原请求须先恢复。

## 验证范围与后续记录

本地只运行受影响的构建、Panel/UI、owned checkpoint、Inspector 及协议回归。
首轮 7 文件 154 项通过；后续审查修复及新增保护采用对应定向回归，记录首次失败。
Windows 实际浏览器、正式 MCP 读回、最终源码身份与未测范围在验收记录中另列，
不能仅从这些 Node 结果推导真实鼠标或真实材料准确性。

不读取未经授权的私人样品。数值测量、可靠性和物理解释仍分别表达；导航不改变旧
科学对象、原始数组、测量记录、标定来源或请求 ID。

## What now works

An original explicit image/frame can enter without a complete structure field.
The formal manual path, `image_discovery(entry="manual")`, records actual
researcher attention with exact original coordinates, scale/settings, reasons,
hypotheses and unknowns. The runtime Agent selects existing FFT/peak/measurement
tools; `image_discovery_review` binds their actual saved evidence to the exact
source/ROI/calibration and returns existing Panel views. Source arrays remain
read-only and provider journals remain the sole request authority.

The historical automatic software checks below verify bounded operation,
evidence binding and recovery, not reliable anomaly detection. That entrance is
EXPERIMENTAL even when those engineering checks pass.

Qualified fixed-g GPA can hand off to the existing F4 method-plan mechanism.
One actual worker test performs that admission and recovers its original IDs
without another source FFT. A fitted reference is not advertised as a qualified
fixed-g handoff. These are optional tools, not a forced automatic pipeline.

## Historical experimental comparison — do not hide the misses

The source formulas and evaluation support were fixed before detector scoring.
The image entrance uses64px only; the field uses four128px windows covering the
whole image plus the existing domain map. Manual attention/control is supplied
from the formula, explicitly **oracle-assisted**, not an autonomous competitor.
Costs differ and are all reported; this is not an equal-cost superiority test.

| Case | Image-first64 | Existing field | Manual attention |
| --- | --- | --- | --- |
| Same-carrier amplitude/contrast depression | MISS,0 candidates | MISS,0 boundary bands,0 unknown samples | HIT |
|15° orientation interface | MISS,0 candidates | HIT,2 support bands for one interface | HIT |
| Clean texture |0 false attentions |0 false attentions |1 deliberately supplied control attention |
| Fixed-seed white noise |0 false attentions, quality-limited |0 boundary bands,4 unknown samples |1 deliberately supplied control attention |

Neither a manual control ROI nor a field support band asserts a physical defect.
The field's amplitude-depression miss is not an unsampled-gap result: all pixels
are covered and the carrier geometry is unchanged by construction. Empty image
proposals likewise do not establish normal structure or defect absence.

Actual entrance preparation was about2.64–2.75s for image-first (zero FFT),
21.24–23.62s for the field (65536 initial FFT pixels) and1.66–1.78s for manual
recording (human selection effort unknown, not free automated search). Selected
verification costs another4096 FFT pixels plus peak/measurement work. Five such
verification FFTs were executed across the12 entrance/case combinations.
See the [exact CSV](examples/discovery/primary-comparison.csv),
[summary/source hashes](examples/discovery/primary-summary.json).

### Separately labelled scale diagnostic

After observing the64px miss, one **post-hoc, truth-known** call tried `[32,64]`
on the same amplitude image. It proposed four32px supports around the single
depression (each descriptive IoU≈0.391), in2.730s with zero FFT. Those four ROIs
are not four independently discovered anomalies. Changing the minimum window
also changes the saved tensor-smoothing aperture8→4px and the sampling grid;
this diagnostic does not isolate one causal parameter.

All extra feature work and the unchanged primary-report/source/FFT hashes are
preserved in the [separate report](examples/discovery/scale-diagnostic.json).
It neither replaces the failed primary result nor supplies blind performance
evidence. Thresholds, noise seed and original truth were not retuned.

## Historical actual new Agent, not automatic-detection qualification

A separate192² float32 public analytic input was generated before its model run.
Its source filename is generic and its formula/truth file was withheld. The
fresh installed Codex session received only the actual image path, finite
budgets, public Skill text and formal MCP tools, with no sample IDs or expected
action/ROI answer. It received actual image content from image_preview.

It independently chose feature windows `[64,96]`, selected `[64,64,128,128]`,
performed one Hann/mean-subtracted4096-pixel FFT, detected four peaks and selected
two nonconjugate peaks for saved measurements. Periods were approximately8px;
nm/d-spacing stayed unknown. It saved a review and stopped pending physical
calibration/acquisition context, without claiming a phase, twin or dislocation.
The tool trace contains nine actual calls; the provider ran no hidden model.

Another actual new model had only image_info/image_result available. It recovered
the original identities, evidence and limits. Independent verification matched
creator/payload hashes, all58 existing files/journals and the source TIFF, with
no replay or new science. The model FFT independently matched a direct finite
DFT (maximum2.92e-13). This separate positive software path is **not** substituted
for the registered256px comparison's misses.

Both sessions used `--ignore-user-config`, explicit local allowlists and
per-tool approvals, a read-only shell sandbox, and exact provided Skill text.
Global config SHA before/after remained identical. No installation/discovery or
browser capability is inferred from these calls. See the
[actual model trace and source digests](examples/discovery/fresh-agent.json).
The last defensive extreme-float finite-statistic guard was tested separately;
an explicit current-scale attachment to an unchanged FFT was likewise checked
with its own focused regression (old-scale evidence still refused,0 new FFT).
These do not alter ordinary mathematics or thresholds. Executed-source hashes
and raw source snapshots are retained instead of retroactively relabelling
earlier model evidence as a different executable.

## Failures retained

- A coherently rehashed direct measurement with changed points initially passed
  review. Fixed with existing committed_measurement/original-request checks and
  numeric summaries; regression now passes. Source/ROI/handoff/history tamper
  tests remain strict.
- r1 export acceptance failed because JS normalizes signed zero while the
  authoritative Python JSON retains it. The corrected r2 assertion is stronger:
  exported JSON bytes must equal the immutable original exactly. Scientific
  tolerances were not changed. r1 remains FAIL under ignored analysis.
- The original r2 presentation read quality from the wrong optional field.
  A separately hashed read-only supplement recovered actual quality status and
  preserved every request/object/FFT and the r2 report. The future harness uses
  the actual quality.status schema; science was not repeated for that change.
- An extreme finite float64 outlier caused nonfinite spatial statistics. Final
  code refuses them before publication; the negative regression retains that
  failure instead of returning invalid JSON or weakening validation.
- A final compatibility check exposed a second exact catalog list still missing
  the two intentionally added tools. Only those two names were added to that
  explicit list; frozen scientific/schema assertions remain unchanged.

Raw records/failures remain in ignored `analysis/2026-10-31-f4b-*` directories.
Only public synthetic summaries, CSV and actual generated PNGs are committed.

## Reproduce

Use a checkout of this dependent feature branch; #44 is its base, not an extra
old branch to cherry-pick. Build once, use an independent Python environment:

```powershell
npm ci
npm run build
$env:MICROSCOPY_PYTHON = 'C:\independent-env\Scripts\python.exe'
python -B tests/test_image_discovery_core.py
python -B tests/test_image_discovery_workspace.py
$env:MICROSCOPY_SMOKE_OUTPUT = 'C:\scratch\f4b-new'
npm run test:discovery
```

The focused handoff test uses optional requirements-gpa.txt; the ordinary
discovery/FFT route uses requirements-images.txt. Ordinary compatible clients
load the same existing plugin/server and updated microscopy-automation Skill;
the two tools register automatically, with old direct tools unchanged.

The opt-in developer `tools/qualify_discovery_agent.py` accepts an explicit local
plugin config plus `--source` or an original `--handoff`, and a new `--output`
directory. It does not edit global configuration, install a model or run inside
the scientific backend. Exit0 alone is never acceptance; verify actual events
and immutable scientific records as done above.

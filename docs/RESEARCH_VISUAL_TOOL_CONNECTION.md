# Minimal visual-input and scientific-tool connection

This plan uses the existing provider, app-server adapter, journals, saved views
and explicit human lead editor. It introduces no agent or numerical engine.
The native entry now supports the fixed public synthetic full image through an
accurate local preview, a separate native menu intent and a cancel-default send
confirmation. Other image inputs still record local scope only. On 2026-11-08 the
owner explicitly authorized retrying public synthetic development tests. A fresh
independent code review and two explicit official-runtime trials followed; the
second completed real image input plus model-chosen ROI statistics and original
request queries. No real specimen image was sent. Missing historical refusal
records are no longer used to block this authorized public-fixture work.

`createPublicSyntheticJointHost` is the explicit development-only real branch.
It admits only the exact full public 64x64 uint16 intensity array, uses the fixed
installed official client/model and existing authentication, reuses the original
joint gate/grant, and validates effective read-only configuration, no MCP tools,
recipient overrides and session identity. Native sending reaches this factory only through the original private owner
pipe after the exact review receipt and a separate native confirmation. There
is no HTTP send action or renderer-supplied approval flag.
The first trial closed with no science calls because disabling the official
Code Mode host also disabled dynamic callbacks. The corrected branch retains
that host while requesting other features off. Model `tool_mode` can override
the Code Mode flag: do not describe feature readback as proof of an exhaustive
two-tool official catalog. Our local scientific callback port contains only
`image_statistics` and `image_result`; official orchestration tools may exist.
Native send confirmation/integration has local contract and provider tests;
real desktop qualification is tracked separately. Full effective-catalog
qualification remains separate work. The historical plan sections below describe the earlier
in-memory implementation; they are not a current blanket ban on authorized
public-fixture tests.

## Historical design: split and minimum future connection

The sections through the scope-only owner contract preserve the earlier design
and its test limits. Statements that real delivery was unavailable apply to
those increments. The opening section and final native-public section describe
the current entry; real GUI acceptance remains separate.

Before the joint first-version change, `CodexStdioHost` had two distinct branches: `textTools` registers the
bounded callbacks but accepts only primitive text; approved image input takes
the research dispatch gate branch, which has no scientific callback port. The
desktop public entry additionally enforces text-only input and exact public
full-frame admission. Their legacy behavior remains unchanged. The new joint mode below is available only to an explicit in-memory synthetic peer; production cannot construct a real joint transport.

The minimum eventual product run is one already saved scalar spatial view,
one applied question and one model turn containing result-driven tool calls:

1. In the Panel owner process, settle published drafts and confirm the exact
   applied question/view/frame. A crop is its explicit saved integer source
   support, not the floating drag, PNG size or viewport. Keep the original source
   read-only. Do not silently create a clean image or remove annotations.
2. Prepare the existing saved-image input and show the exact image/question,
   allowed scientific scope and outgoing data. Only an explicit owner-controlled
   confirmation may approve it. Metadata readiness or a browser-supplied boolean
   is not approval. The existing gate requires a synchronous live owner read in
   the same process; an HTTP snapshot or another process's cached state cannot
   supply that guarantee.
3. Use an explicit research-with-tools adapter mode, sharing the existing
   callback implementation and safety restrictions. It must accept the opaque
   approved turn handle, register only the reviewed catalog, keep shell/web/
   arbitrary tool access closed, and retain the final gate immediately before
   stdin acceptance. Do not relax the existing text-only branch.
4. Route callbacks on the exact current thread/turn to the fixed saved-view tool
   scope. Return whitelisted original statistics, hashes, source coordinates and
   original request IDs. Do not return pixels, PNGs, paths or arbitrary provider
   responses through tools. Let the model choose another permitted measurement
   from the actual returned values within the same turn.
5. Present the answer and exact results as separately inspectable records. Reuse
   saved statistics history, exact input navigation and manual explanation/lead
   editing. A model answer is not automatically a hypothesis, supporting
   relation or accepted scientific conclusion. Workspace Save stays explicit.

## Historical first increment: local connection

`createSavedViewResearchTools({registry, workspace, frameId, viewId,
journalDirectory})` in `lib/research_text_tools.mts` exports a local scientific
port. It shares the existing text tool execution/recovery implementation; there
is no new host or sending entry. `createResearchTextTools` and desktop public
admission retain their historical frame/full-frame behavior and context digest.

The local factory requires an exact committed ordinary `view`, one spatial
source grid on the supplied frame, scalar dtype and consistent in-frame integer
support/shape. It refuses annotations, reprojection, composites, contradictory
domains and raw-frame fallback. It verifies scientific array hashes through the
existing reader. Creating this scientific scope does not open a PNG or claim
its visual qualification. Result recovery reuses the existing statistics-history
reader, which may hash a saved preview for its display projection; the tool
response drops that display field and never encodes or forwards PNG bytes. A
missing or invalid visual input must still fail the existing separate image
preparation boundary before any eventual disclosure.

The port has only `image_statistics` and `image_result`. Its immutable
`input_scope` contains exact input/frame identities, input manifest hash and
`source_rect_xyxy`, with `disclosure_approved:false`. The new scope digest also
binds the exposed tool definitions. This digest is not an approval handle and
cannot replace the research gate's reviewed context digest.

Statistics omit `rect` for the whole saved support, or use absolute source-pixel
half-open bounds inside it. For a saved crop `[5,6,15,14]`, `[0,0,10,8]` is not a
relative-coordinate shorthand: it is refused before a provider request is
assigned. No clipping, translation, raw-frame substitution or re-render occurs.
Result projections retain the existing input/result/request hashes and source
range; they do not change provider schemas or historical IDs.

## State and unknown outcomes

Before write: changed source bytes, invalid bounds, cancellation or an unresolved
original outcome yields no new scientific dispatch. Once a request is assigned,
its identity is journaled before provider execution. A lost or unverifiable
reply keeps that original ID unresolved. Duplicate tool call IDs return the
original outcome; new writes are fenced. Only `image_result` for an original
request owned by this port may recover it; queries never repeat statistics.
The bridge freezes canonical normalized request parameters before handing any
argument arrays to a provider. Both initial successful projection and later
`image_result` require the committed successful journal's parameters to equal
that original string, including action, input, request ID, workspace and whether
rect was omitted. Journal/result self-consistency and being inside the crop are
insufficient: another in-bounds ROI must remain unknown. A provider callback
cannot change the expected parameters by mutating its arguments. If a later
query no longer matches a previously completed request, it re-establishes the
unknown-result fence; only exact success or a verified terminal failure clears it.
Every audit append stores a separate deep snapshot, and provider dispatch gets
its own deep argument copy. In-place or retained provider argument mutations
cannot rewrite an earlier intent or a later completion audit when the log is
persisted again. The audit reader also returns copies; it cannot change the
original request, journal or unknown-result fence.
Verified terminal failure permits a corrected new request under the existing
contract. Cancellation and late replies retain original scientific evidence.

The host still validates exact thread/turn before dispatch and delivery. This
local factory fixes scientific source scope, not a live question, consent or
host identity. Eventual owner integration must fence new writes when approved
question/source scope changes, while retaining original read-only recovery.
An already accepted write cannot be unsent. Unknown model-turn outcomes must
not start replacement turns or be relabeled completed by UI wait timeouts.

## Historical decisions before real vision (superseded by native public version)

The combined adapter mode needs a reviewed contract for approval to cover both
the image payload and tool catalog/bounds, rather than pretending the existing
image digest and new tool-scope digest are interchangeable. It also needs an
owner-controlled confirmation route, per-callback scope lifetime and stop/close
coordination. These are cross-layer approval/lifecycle decisions; this increment
does not alter the image gate, adapter modes or production endpoints to implement
them. Keep the first experiment to one approved question/turn. New questions or
images need explicit new scope; current session/task binding cannot be silently
rewritten for follow-ups. The old blocked review is not retried by this work.

The owner must compare the prepared image and tool scope's exact saved view,
manifest, frame, array identity and source rectangle before reviewing the joint
scope. Same-frame identity alone is insufficient. Existing public UI source
navigation has full-frame defaults and public-only admission; a future visual
session must supply its explicit scope rather than reusing those defaults or
silently widening the public sample entry. The manual exact-reference editor
and provider journals remain the reusable result boundary.

## Historical scope-only owner contract (superseded by native public sending)

The native desktop now offers “预览本次图像与工具范围…” for one applied question
and its exact saved single spatial view. This is **local scope review only**.
`JointResearchOwner` lives in the Panel owner process, reuses image preparation,
the existing send gate, scientific runtime and saved-view tools. It checks the
working/draft/window/source leases synchronously, holds the image/question
immutable, and expires the pending review after at most five minutes.

The main process requests `prepare-joint-review` from the owned main frame,
then uses a private stdio command to prepare the scope. The renderer sees only
fixed no-argument `reviewImage()` / `stopImageReview()` intents. No HTTP approve,
send, start-turn or serialized boolean authority is exposed. A random read-only
preview URL serves the exact bound PNG and escaped text with no JavaScript,
preload or outgoing connections. The parent window is disabled during review.
The user can scroll before using the native “分析 → 记录已核对本次范围（不发送）”
menu; a separate cancel-default native dialog then records the exact review ID
and digest. Close/menu Cancel revokes the URL. This receipt is named
`native_scope_review_only`, never an external-send grant. It cannot later start
even the synthetic run. Ordinary browser entry does not expose this native UI.

`reviewJoint` binds exact prepared PNG/question/source, immutable original saved
science-port identity, source support, tool definitions and owner lease in one
context digest. `approveJoint` creates the same process-local one-use grant
pattern as the image gate. Adapter modes cannot exchange grants. The actual
write rechecks the owner and exact port after the final observer; callbacks
recheck them before scientific dispatch and before delivering results. A local
owner change after a scientific write keeps the original audit and fences the
host; it never resubmits. The existing source-coordinate, request-parameter and
journal identity checks remain authoritative.

`CodexStdioHost({jointTools:{tools}})` refuses real construction. Its only enabled
joint contract requires `verification:'synthetic'` and an original unused opaque
peer from `createJointResearchMemoryPeer`. Arbitrary `spawnProcess` functions
(including Node's real spawn or a wrapper) and process configuration are refused
at construction, even with that peer. The module retains the actual streams
privately, with native private host fields and writer; connect selects this fixed in-memory child and cannot choose an OS
process. Copied/fake/reused peer handles are refused. `JointResearchOwner` also
checks the original host/port identity before connect, rather than trusting a
synthetic snapshot label. Joint protocol observers receive only method/request IDs, never image, question or
result payload. Immediately before each tool reply write, after observers and
serialization, the owner, port and active turn are checked again; a failure
retains the original scientific audit and writes no reply. Local read-only peer
inspection remains available for tests. This is a fixed transport boundary, not
an OS sandbox against arbitrary trusted JavaScript outside the adapter.
No environment toggle enables real delivery. `runSynthetic` is an
internal local test entry, absent from all native/public commands. Synthetic
messages and native scope records carry distinct authority labels. No native
user decision in this version calls `approveJoint` or `startTurn`.

Operational statuses are separate from scientific/AnalysisContext revisions:
reviewing / starting / running / stopping / unknown lock mutations; a query can
expire a preview but never replay it. Interrupt acknowledgment retains the lock
until the original terminal notification. Unknown remains fenced, including
late callbacks. The owner distinguishes scientific waiting from transport or
protocol unknown. It records the exact terminal thread/turn/session/status when
only scientific requests are pending. If their exact original audits later
resolve, query restores that same known terminal state without any new write or
reply delivery. Wrong parameters, unresolved requests, a different terminal
identity, or an independent host failure keep the owner locked. A terminal host message cannot clear an unresolved scientific request: the audit is folded by exact original request ID, and any outstanding write keeps the owner unknown and locked. Existing statistics history is readable while inputs are
locked; navigation/editing is refused. Answers and whitelisted tool outcomes
are rendered as text, with original request/result/frame identities; they are
not automatically accepted into hypotheses or evidence relations. Local
`research-runs/joint-<id>/owner.json` and existing tool audits record scope/lifecycle
and original outcomes. The local frozen review reference retains the exact question, source IDs/hashes and source-pixel/tool scope, with no image data URL or preview token. These owner logs are not provider scientific journals,
not restored grants, and do not yet have a cross-restart task-history UI.

The added `research-joint`, `desktop-joint`, UI and actual-provider tests qualify
only these layers. A public generated crop `[5,6,15,14]` through one in-memory
image/tool turn returned mean 959.5 and its exact original query; this is real
local Python computation, not model vision. Native public-fixture preview,
cancel, save and reopen were also exercised. Real external image delivery,
actual model image receipt/reasoning and the original independent security
review remain **NOT_TESTED / blocked**. Resolving that original refusal and
establishing a permitted route with concrete per-image owner confirmation must
precede any real send; current scope receipts cannot be reused for it.

## Native public first version and saved results

The main process previews the exact original receipt, then requires the native
“发送本次公开合成图并分析…” intent plus a cancel-default dialog.
`sendPublic` accepts only that still-pending receipt and the fixed public full
array. A previous scope-only record cannot become permission. It returns a
starting receipt promptly while the original host is prepared; connect/account/
session/current-state checks still precede the one-shot image turn. Input stays
locked while starting/running/stopping/unknown. Interrupt rejection or pending
science cannot be overwritten as a terminal unlocked state.

Owner records and scientific journals persist locally. Reopen reads bounded
saved owner metadata and revalidates numeric results with the existing
`readImageStatisticsHistory`; no model connection or scientific replay occurs.
An incomplete, corrupt or unverified previous run preserves an unknown fence.
Model text, verified numeric cards and original references are presented
separately. Ctrl+S continues to save the existing image/question analysis
savepoint; scientific execution and the original model run are already retained
in their respective local records, without automatically adopting evidence.

An out-of-session `image_result` now returns `QUERY_OUTSIDE_SESSION` with
`queried_request_outcome: not_checked`: the query was refused, not the original
execution. The UI repeats this distinction and offers same-frame history for
earlier source/display records. No broadening of the model query scope occurs.

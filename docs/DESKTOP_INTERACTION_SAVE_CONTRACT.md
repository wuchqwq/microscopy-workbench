# 桌面交互与保存合同（短 ADR 草案）

状态：**待用户批准，未实现独立保存生命周期**。2026-11-03；依据 [#89](https://github.com/wuchqwq/microscopy-workbench/issues/89)、[#90](https://github.com/wuchqwq/microscopy-workbench/issues/90) 最新正文及附件研究材料。
本轮源码审读基于 `78ba035b661540165b29be666824c0ef49d32032`，不是 main 或已合并基线；不授权合并现有 PR。本文不宣称保存闭环或用户报告的缺陷已验收。
范围：同一源帧的多个 ROI、空间视图与 FFT；沿用 TypeScript `.mts`、正式构建及现有科学服务。桌面/真正 headless CLI 属于 [#91](https://github.com/wuchqwq/microscopy-workbench/issues/91)，安装分发属于 [#92](https://github.com/wuchqwq/microscopy-workbench/issues/92)。

## 1. 建议的操作合同

下表是拟议行为；“当前实现”列描述 `78ba035` 基线。画框回选择、删除和命中等局部缺陷另行修复；这些小修不代表新的工作区保存合同已经实现。尚无的保存或菜单能力不得提前显示为可用。

| 用户动作 | 拟议行为与保护 | 当前实现的落点/差距 |
|---|---|---|
| 打开/恢复 | 明确源文件、帧和工作区；先显示可验证的保存版本 | Inspector 已绑定源与启动参数；恢复仍以最新 checkpoint 为主 |
| 画 ROI | 默认“选择”；画完回选择；连续画框需主动开启 | `app.mts` 目前松手调用 `createRoiGeometry()`，读回后重回 ROI 模式 |
| 选择/移动/缩放 | 内部/边框可选，内部拖移、控制点缩放；命中尺寸按屏幕像素；重叠时用 ROI 小列表明确选择 | 复用 `roi-editing.mts`；FFT 计算范围是只读辅助线，不抢命中 |
| 删除/撤销 | 仅画布焦点下的已选 ROI；无选择不删除；文本框 Delete/Backspace 仅编辑文本；手势一次撤销；Escape 取消未完成手势 | 复用 `UserActionHistory`；当前键盘分支没有 ROI Delete；不得删除历史输入/结果 |
| 点击另一窗口 | 置顶并受保护激活；首次点击只激活，解码与对象一致后才编辑；正常换窗保留各窗工作编辑 | 现有 `activateWindow()` 会拒绝本地理由/坐标/显示草稿；需明确扩展工作状态，不能直接取消校验 |
| 临时 ROI → FFT | 不要求先“保存 ROI 观察”或填理由；冻结实际输入后调用现有 FFT | 当前临时选择可计算；以后不得把创建不可变输入对象等同于用户保存 |
| 修改峰 → 测量 | 改峰不改旧数组/测量；建议明确点击“测量/重新测量”产生新记录 | 当前 `flushEdits()` 后可能自动 `remeasureSavedEdit()`；此规则需决策 3 |
| 返回空间图/比较 | 复用现有历史、`return-spatial` 和“查看最新 ROI”；历史输入与最新工作版明确区分 | 不从 FFT 整数范围倒造原浮点 ROI；不增加第二套导航 |
| 保存/Ctrl+S | 保存整个分析工作区的准确版本；成功读回后才提示“已保存” | 当前“保存 ROI 观察”是局部对象与交接校验，不是此动作 |
| 关闭子窗 | 只隐藏显示，保留该窗工作编辑与科学记录；关闭最后子窗不删除工作区 | 当前 collection 会移除只读窗，且禁止关闭活动窗；需将视图可见性与工作内容区分 |
| 退出工作区 | 有修改时保存/不保存/取消；保存失败不退出；未决执行单独处理 | 浏览器 `beforeunload` 只能通用阻止，不能承诺三选项或强制终止提示 |
| Agent 接续/导出/帮助 | 交接明确版本/临时快照；导出图面或数组不等于保存工作区；帮助不改选区、不计算 | 复用 `ResearchWorkspace`、`/api/roi-handoff`、既有导出与中文帮助；不新增 Agent 队列 |

## 2. 保存单位、三层状态与一个写入权威

**推荐按分析工作区保存**，子窗口只是该工作区的视图。原始 TIFF/DM 文件和科学数组只读。

| 层 | 权威/内容 | 不表示什么 |
|---|---|---|
| 工作编辑（working edits） | 工作区所有者持有各窗基对象/网格/标定版本、稳定 ROI 身份/几何、笔记、选用结果及撤销状态 | 不因松手、换窗或恢复快照就成为用户保存点 |
| 显式保存点（savepoint） | 小型版本化引用清单，记录用户确认的完整分析版本与引用校验信息 | 不复制科学数组，不把所有已执行结果自动纳入分析 |
| 不可变执行记录 | 既有 provider 对象/journals：实际输入、浮点 ROI、整数处理范围、标定版本、参数、原 request_id 与结果 | 不证明 GUI 已接纳、用户已保存或物理解释已确认 |

建议同一工作区仅由一个已确认所有者串行发布工作状态、保存点和采用决定；GUI/后续 CLI/MCP 都经过此入口，provider 继续拥有科学记录。
各窗口可以保留未保存编辑，但只有一个活动编辑租约，**不是每窗一个写入队列/worker**。在现有 collection 内扩展版本化工作内容，而非另造导航或科学数据库。
切窗时先结束/取消正在进行的手势，将离开窗口的编辑可靠停放到该工作区工作状态；版本核对后推进全局 lease，再接续目标与解码。停放不是显式保存，也不能靠伪报 `dirty=false` 绕过现有保护。
同一张历史图上的新工作版本需有明确基版本；不能把旧 FFT 输入就地改成“最新 ROI”。非活动窗不接受科学手势，旧异步响应不能写入新活动窗。
读取/解码失败保留上一幅已验证图像并结束 loading，显示失败原因与既有保存资产的只读重试入口；重试不提交 FFT，也不解除未决写入保护。
已有 `busy`、全局 `draft_revision`、单进程 `ExecutionCoordinator` 和每 Panel 的注册锁都**不等于跨进程工作区写锁**；#91 接入其他入口前必须完成所有者绑定/冲突拒绝，不能各自创建 coordinator 后声称共用权威。

建议保存点含：源帧引用、各窗工作版本、ROI/理由（空理由仍 unknown）、标定引用、明确采用的 FFT/测量引用，以及决定 2 所选显示内容。相机/窗口尺寸/平铺单列偏好，不因每次平移把科学工作标 dirty。
临时 B 计算时可用现有标注/输入对象机制固化准确快照，再调用现有算法；这是执行输入留档，不是隐式 Save。后来的 ROI 改动永不重写旧 FFT 的 frozen context。

## 3. 保存、退出和恢复状态表

`r` 为拟议的整个工作区工作版本；现有 `state_revision`、`draft_revision`、`collection_revision` 各自保留用途，不能拿其中一个冒充全工作区版本。

| 起点/事件 | 处理与最终状态 |
|---|---|
| clean → ROI/笔记/采用决定改变 | dirty；保留基保存点和工作版本，撤销不删除已经执行的记录 |
| dirty → 保存 | 冻结快照 r 和原 save_id，持久化保存意图，进入 saving(r)；不顺带触发 FFT/重测 |
| saving(r) 时有新编辑 r+1 | 仅发布 r；读回成功仍 dirty(r+1)，不得清掉新编辑或显示全部已保存 |
| saving(r) 完成且无新编辑 | 读回清单/必要对象、网格、标定、引用和保存点指针一致后 clean(r) |
| 已知保存失败/结果未知 | 保留编辑；失败不退出。未知保留原 save_id，读取其发布结果，禁止换 ID 重放 |
| dirty → 关闭工作区：保存 | 按上述保存完成并再次确认无新编辑才关闭；新编辑则继续询问/保持打开 |
| dirty → 不保存 | 可靠记录本次工作版本已丢弃，回到上个显式保存点；保留执行历史与原请求，不自动采用新结果 |
| dirty → 取消退出 | 工作内容、活动窗、选择与执行状态均不变 |
| running/unknown → 退出 | 保留原 request_id；等待/查询原请求/保持应用打开；支持的取消也不证明未执行，不通过导航或“不保存”隐藏它 |
| 正常重开/崩溃重开 | 正常重开读取显式保存点；崩溃草稿单独提示“未保存恢复”，明确选择后才恢复；故意丢弃的版本不再无提示复活 |

保存点发布建议由同一工作区所有者完成：验证必要引用 → 同目录临时清单写入/同步 → 原子发布版本清单与当前指针 → 实际读回；清单只含引用及必要工作元数据。
先设计并验证保存意图/发布指针的失败恢复与前保存点 CAS；一次 rename 或两次 `/api/state` 读回本身不证明多文件事务或跨进程排他。
已完成的科学对象即使未被采用也留在既有对象/journal 历史；不新增一套历史。未完成执行的身份必须先可靠留存，当前版本不确定时保持窗口打开。
丢弃标记需绑定基保存点、工作版本及会话代次，阻止晚到响应重新采用 B；此标记不篡改 provider 的成功/未知状态。

### 必须满足的反例（设计合同，NOT_TESTED）

| 操作 | 重开后的要求 |
|---|---|
| 保存 ROI A | 明确保存点 S(A)，确认读回；“A”指分析状态，不是改写原图 |
| 编辑为 B，直接 FFT(B) | B 仍是工作编辑；FFT 固化 B 的真实浮点输入、整数范围、参数和标定 |
| 选择“不保存”退出 | S(A) 不动；工作 B 记为已丢弃；FFT(B) 与 B 输入留在执行历史 |
| 重开 | 恢复 A；FFT(B) 可明确从历史查看，但不改标为 A、不自动纳入 S(A)、不自动恢复 B 草稿 |

| 现有组件 | 可以复用的职责 | 批准后需要补齐的合同 |

| [`researcher_inspector.mts`](../tools/researcher_inspector.mts)、[`panel_ownership.mts`](../lib/panel_ownership.mts) | 准确源绑定、原启动请求回查、helper 代次/锁、正常关闭与 checkpoint 校验 | 目前正常重开采用最新 checkpoint；以后区分显式保存/恢复/已丢弃；helper 所有权不冒充工作区写入权威 |
| [`tool_registry.mts`](../lib/runtime/tool_registry.mts)、[`execution_coordinator.mts`](../lib/runtime/execution_coordinator.mts)、[`image_workspace.mts`](../lib/image_workspace.mts) | 共用 schema/处理入口、单进程 resourceKey 串行、不可变参数、worker 与等待者状态、原请求 query | 保持 provider journal 权威；复用入口绑定唯一工作区所有者；不新建事件框架或平行科学服务 |

旧工作区无保存点时标记“旧版自动恢复记录”；只读打开并核对原引用，用户明确首次保存后才建立新保存点，不能补造历史 Save。
迁移采用版本化派生元数据/备份，失败不覆盖旧 checkpoint，不把缺失标定、浮点来源或保存资格猜成有效。未知请求、旧对象和哈希保留原样。
审批后的验证只围绕 UI/状态/持久化/恢复及必要 provider 边界：保存期间新编辑、失败/响应丢失、晚到结果、A/B 换窗、目标解码失败、丢弃后重开、旧档迁移与键盘焦点。
本文仅做源码/资料审读与设计；未运行保存生命周期替身、科学套件或浏览器手势，不把设计场景标 PASS。

## 5. 低保真布局（拟议，无新增运行功能）

```text
文件    编辑    分析    窗口    帮助       工作区名 * [保存]
选择    ROI    测量    平移             当前：来源图 / ROI 2
┌────────────────────────────────┬─────────────────┐
│ 来源图：ROI 1、ROI 2             │ 属性/观察 [收起] │
│           ┌ FFT(ROI 1) ┐         │ ROI 小列表       │
│           └───────────┘         │ 显示/理由/标定    │
│   ┌ FFT(ROI 2) ┐                │ 详细来源 [展开]  │
└────────────────────────────────┴─────────────────┘
测量结果 [折叠]    未保存修改 / 保存中 / 保存失败 / 原请求待核对
```

菜单、快捷键与现有按钮最终调用同一动作；复用 `WindowWorkspace`、抽屉与结果区，先合并重复入口，不提前大改架构或新增 React。

## 6. 仅需用户确认的三项

1. **保存单位**：推荐同源帧“分析工作区”整体保存，关闭子窗只隐藏；是否接受这个范围，而非每个子窗分别保存？
2. **显示内容**：推荐显式保存包含标注样式、图像显示配方和采用结果；相机/平铺/面板开合独立作偏好恢复，不触发科学未保存提示。是否接受？
3. **峰修改后的计算**：推荐手势只修改工作峰，用户明确“重新测量”才执行并追加结果；是否保留目前部分场景的自动重测？两者都不得覆盖旧测量。

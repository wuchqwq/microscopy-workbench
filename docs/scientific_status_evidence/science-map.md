## Main finding

In this Python scope, `valid` is primarily a numerical/support predicate, not a qualified lattice measurement. The code generally already says this explicitly in nearby limitations. There is no observed Python assignment that turns a feature `valid` directly into a confirmed material phase. The risk is loss of those qualifications when a consumer retains a short status, mask or count and discards its scope. A shared additive contract is warranted; changing thresholds, replacing legacy statuses, or blocking all candidate discussion is not.

The most consequential chain is:

`peak numerical amplitude variation + local maxima` → selected geometric vectors → feature sample `valid` → domain-map `candidate` → active-analysis `usable_observations`/`new_valid_observations` → heuristic continuation or stop.

None of these transitions evaluates noise significance, localization uncertainty, or whether image contrast originates from a single material lattice. The last transition is permitted as exploration, but cannot be described as acquiring reliable or independent material evidence.

## Priority semantic risks and classifications

1. **Feature `valid` → graph `candidate` → policy `usable` loses layer distinction if summarized carelessly.** Files and predicates above establish the risk; this audit does not claim a newly reproduced calculation bug. Classification: output/consumer semantic ambiguity plus unassessed measurement reliability. Minimal response: attach common scoped numerical and reliability summaries; label counts as numerical/geometry support. Preserve legacy status and the current optional exploration policy. Noise-generated numerical maxima can satisfy these predicates without proving periodic material structure.
2. **Legacy `incompatible` can mean unavailable physical calibration.** Classification: historical semantics/version-compatibility hazard, already corrected for new local-signature v2 production. Minimal response: an adapter must respect v1/v2 and reason codes; historical viewers say the field's original meaning/assessment absence. No blanket migration, recomputation, or claim of physical conflict.
3. **Several valid/verification names describe unrelated predicates.** `period_valid`, feature `validity_mask`, domain candidate mask, GPA tensor mask, topology loop `valid`, coordinate `VERIFIED`, and `material_strain_verified=False` cannot share a boolean interpretation. Classification: semantic scope risk. Minimal response: explicitly enumerate checked scope; “not assessed” is neither “passed” nor “failed.”
4. **Direction diversity is not frequency-band independence.** The method policy's proposed redundant direction uses a bounded geometric heuristic; actual v3 checks masks. Classification: method/admission limitation, not a reproduced new bug. Minimal response: report the policy's selection intent separately from the executed v3 check. Do not relabel old direction-count output as certified independent evidence.
5. **Single-direction measurements and physically uncalibrated measurements remain useful.** A two-family feature failure or absent physical calibration must restrict that claim only. Classification: task scope/measurement information insufficiency. Pixel-domain period, image-coordinate angle, observed contrast and candidate discussion can continue. Avoid deriving a whole-object failure from a missing qualification of one conclusion.

No new implementation bug is claimed from this static audit alone. No measurement error distribution is newly quantified. Known method limits include finite window/aperture, uncalibrated peak significance/localization, selected finite-angle comparison, conditional single-domain GPA, and sampled phase circuits. Physical non-identifiability includes contrast versus displacement origin, distinct structures sharing projected reciprocal geometry, zero net phase winding versus defect absence, and projected versus unique 3D Burgers vectors. These are separate from data-integrity errors.

## Minimal additive contract hooks

Use one shared, deterministic, bounded builder/schema rather than another free-form status vocabulary per algorithm. Existing algorithms retain their statuses/thresholds and primary result values. A new versioned assessment should contain three separate scopes, each with evidence references/reasons:

- **Numerical calculation/checks:** name the actually executed calculation and checks, retain original algorithm/status and checked scope. Distinguish computed, failed/admission insufficient, partial support, and unknown historical assessment. It must never claim a check was performed just because an object exists.
- **Measurement reliability:** separate noise/significance, localization uncertainty, resolution, parameter sensitivity, calibration uncertainty and source dependence as applicable. Each item is either assessed against an explicit saved criterion with outcome, assessed with issues, not assessed, or insufficient information for that particular assessment. Current peak ratio and interpolation are diagnostics; they are not numerical values for these unknown qualifications. An absent calibration limits physical units, not pixel geometry.
- **Candidate interpretation:** candidate/observation origin, exact evidence IDs, declared assumptions, checks actually run, finite compatibility/conflict and unresolved alternatives. Default is no physical confirmation; `hypothesized` is not a failed hypothesis. If no interpretation was supplied, say not assessed instead of inventing an explanation. Multiple derived objects retain common source/dependence.

A safe narrow first implementation can cover peak/measure/feature/GPA summaries and a common transport/view layer, leaving unsupported producer summaries explicitly absent. It must not fabricate complete per-module assessments to make an interface appear uniform. Unsupported and legacy absence should render as “assessment not recorded” without modifying saved objects. If read-time information is derived, label it as a separate current view with evaluator version and exact input hash; never inject it into the historical authoritative record.

History rules are already intentional: peaks `require_current` demands an explicit new request for new numerical assessment; local signature semantics version preserves v1; GPA views copy only actual assessment fields; topology retains v1/v2/v3 algorithms and checks original histories; domain neighbor-policy omission preserves original graph rules. The shared contract should follow that pattern. An old object's absent new field cannot become “failed,” “qualified,” or a new physical conclusion during restore.

## Retain, limit, discuss

Retain explicit ROI→FFT→measure→finite candidate comparison as the ordinary path. Retain pixel-domain analysis when uncalibrated. Retain discovery/field/GPA/topology/method policies as optional diagnostics with source-bound reasoning. No source evidence here requires a new Agent framework, statistical peak detector or global field prerequisite.

Discuss before expanding: whether an Agent-facing summary needs a statement-level evidence list or a bounded result-level summary with scoped rows. The latter is smaller and sufficient for current tools; the former supports richer candidate reasoning but risks a new evidence engine. Neither design should infer material validity from legacy statuses. Also retain a distinction between a bounded policy choosing to stop and an epistemic conclusion that the image cannot distinguish a specific pair of explanations.

The first three useful changes are: (1) publish the shared scope contract and immutable-history rules; (2) pass existing numerical/unknown/reason/source fields without overclaim through MCP/Panel/Skills; (3) run actual source-blind Agent cases against formal tool results, including single-direction, pixel-only, pure noise, close peaks, stale manual edits and common-source comparisons. Algorithm thresholds need no change merely to make that semantic demonstration pass.

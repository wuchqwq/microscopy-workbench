## 1. Scope and meaning of existing states

There is no single existing meaning of `valid`, `compatible`, or `insufficient_evidence`. In particular, computational admission, physical-unit availability, currentness, object integrity, candidate comparison, and physical interpretation are separate contracts. A new explanatory layer should preserve these original contracts rather than remap their strings globally.

## 2. Concrete findings, separated by failure class

### C1 — Conditional admission can be mistaken for measurement reliability

**Class:** output/consumer semantics; no demonstrated mathematical error here. **Priority:** P1 semantic contract.

`twin_observations._quality()` converts `valid`/`observed`, truncation flags and invalid-reason absence into `evidence_quality_ready`. `general_evidence.assess_side()` then uses that flag and directional geometry for a conditional finite-candidate comparison. These are defensible input-admission checks; they are not a calibrated noise or uncertainty test. A synthetic/noisy observation that passes that checklist can enter a geometric candidate comparison, while reliability remains unassessed. The existing `NOT_VALIDATED` and `phase_identified: false` prevent an explicit phase claim in the saved result, but the broad readiness name and “resolved” wording can cause an Agent or UI consumer to overread it.

**Minimal reproducible source path:** a saved feature sample with status `valid`, empty invalid reasons, detector `selection_limit_reached: false`, detection not truncated, and two noncollinear supplied measurements follows `_quality` → `assess_side`. No noise significance or localization field is tested along that path. Runtime construction of this case is **NOT_TESTED** by this subtask.

**Recommendation:** preserve the original gate and state; add a scoped description of numerical/geometry admission, an independent measurement-reliability layer with explicitly unassessed components, and a candidate interpretation layer explaining finite conditions. Do not convert “reliability not assessed” into global rejection of pixel measurements or candidate discussion.

### C2 — Compact summaries and Panel projections drop the meaning needed by consumers

**Class:** transport/interface gap for the proposed additive contract; a new-field regression would be an implementation bug. **Priority:** P1.

`tools/image_evidence.py:39–47` has a structural top-level whitelist; `73–76` has a sample whitelist; `91–92` has a domain whitelist. They would omit a new shared semantic field. Existing sample `valid_status_meaning` / `interpretation_status` are also not in the sample whitelist. Nonstructural summaries deep-copy the whole record (`50–51`), and bounded detail rows are copied whole (`95–119`), so behavior differs by path.

Ordinary Panel objects are projected by `tools/image_panel.mts:45–47`; GPA currently has a special explicit projector (`37`). Domain evidence preserves the full provider result (`85–96`) but its renderer does not use the scoped meaning. Crystal evidence has separate whitelists at `lib/panel_crystal_evidence.mts:65`, `75`, `76`, `80`. Merely adding a Python field will not complete MCP compact → Panel propagation.

**Recommendation:** one bounded shared projector/rendering contract, explicit preservation at these boundaries, and full/compact/detail/Panel parity regression. Preserve absence and unknown versions. A too-large explanatory object must be reported unavailable with a saved-object reference, not silently truncated into a stronger claim or trigger a scientific retry.

### C3 — GUI labels currently overstate image-frequency observations

**Class:** output wording/interpretation strength. **Priority:** P2 local display.

`ui/image-panel/domain-evidence.mts:18` calls these “反射证据” and “反射几何相容” even though an image FFT's local maxima have not been established as crystallographic reflections. The same panel correctly says they are not phase/twin/dislocation confirmation and that overlapping windows are not independent (`18–19`), but the noun still promotes an unqualified observation. Rows display raw `valid` under “有效性” (`27`, `63–65`) without rendering the field's precise numerical scope.

**Recommendation:** describe image frequency / periodicity / direction candidates; retain conditional comparison language where appropriate. Display numerical scope and unassessed reliability next to the raw historical status, without renaming or rewriting the historical record. `research-workspace.mts:13`, `52–57` already uses the safer “在所给条件下相容” and preserves alternative candidates.

### C4 — Manual entry is conflated with researcher authorship

**Class:** source/actor attribution implementation contract gap for Route A. **Priority:** P2; fix independently with version compatibility if included.

Any formal `image_discovery` request using `entry: manual` is stored with `entry_basis: researcher_statement` (`tools/image_discovery.py:85–87`) and “Researcher attention” (`91–95`), then validated against that exact rule (`271`). The report also hardcodes `researcher-attention-v1` and `researcher_statement_not_numerically_verified` (`136`); the tool description and recipe call them researcher ROIs (`lib/image_discovery_contract.mts:20–27`, `41`). An Agent can legitimately supply those explicit rectangles and reasons. The route tells us that the rectangles were explicitly supplied; it does not tell us who proposed them. The annotation `user_confirmed` enum is also writable by the caller (`lib/image_workspace.mts:58`), while Panel `origin` distinguishes saved annotation vs current selection, not human vs AI (`roi-observations.mts:12`).

**Minimum counterexample:** Agent submits an explicit manual ROI through the same tool schema; the producer labels it a researcher statement without receiving an actor identity. Source inspection establishes the attribution rule; a formal live-tool replay is **NOT_TESTED** in this subtask.

**Recommendation:** Skill instructions must immediately avoid claiming human/AI authorship from these fields. If adding an explicit caller-declared actor/source field, version new discovery semantics and preserve old policy validation/bytes. Do not silently rewrite legacy researcher labels, and do not claim a caller-supplied label is identity authentication. This does not require an Agent framework.

**Versioning detail:** the current global `VERSION` enters the candidate identity hash (`84`) as well as the metadata gate (`253`). Passing the saved policy version explicitly through `_parameters`, `_candidate` and `_manual` is necessary for old read validation (`256`, `269`, `271`); a new default origin must not be injected into v1 parameters. New review records may reference a v1 candidate verbatim (`232–235`, `300–302`); the review's own new version must not reinterpret that candidate. A smaller alternative is v2 neutral `explicit_caller_supplied_roi` wording with authorship only in the existing reason; this avoids a new field but loses structured attribution. An optional `selection_origin` of researcher/agent/unspecified with explicit caller-reported semantics remains a bounded improvement. Keep it separate from the twinning-specific `research_observation` authority contract.

## 3. Existing designs that already protect the scientific boundary

- General candidate comparison preserves multiple compatible candidates as insufficient to distinguish (`general_evidence.py:156–166`); saved objects retain `hypothesized`, false phase/twin/intensity flags (`467–480`). Revision history explicitly says historical parents were not reinterpreted (`599–608`).
- Fixed caller registration, one-to-one assignment, unmatched reflections and ambiguous HKL/projected assignments are retained (`reflection_compare.py:351–364`); registration proposal version 2 separates held-out geometry from independent validation (`registration_proposal.py:321–340`).
- Crystal Panel payload admission rejects stronger physical flags (`panel_crystal_evidence.mts:57–58`), preserves bounded match/ambiguity rows with omitted counts and full references (`70–76`), and labels restored snapshots unvalidated (`215–231`). Its `validated` attachment status is not a scientific validation.
- Full image MCP replies serialize the entire verified worker result (`lib/image_workspace.mts:201–211`); full structure MCP replies do the same (`lib/structure_workspace.mts:109–116`). These do not invent or strip semantic fields. Structural compact projection failure already says the authoritative operation completed and must not be retried (`image_workspace.mts:179–188`).
- GPA has a useful bounded additive precedent: `gpa-evidence.mts:11–31` bounded copy; `50–57` exact field projection or unavailable; missing historical assessment renders `not_recorded` and explicitly does not infer material strain from `valid_tensor` (`96–98`); unknown/malformed versions stay unrecognized (`101–106`). This is a transport/display precedent, not permission to map all scientific modules onto GPA's claim-specific statuses.
- Pixel-domain measurement remains available without physical calibration; currentness checks remain distinct from uncertainty (`measurement-workspace.mts:41–68`). A new reliability layer should not remove this.

## 4. Minimal additive transfer design for the parent contract

These are integration recommendations, not a new schema imposed by this audit.

1. **Store one versioned explanatory field only on newly created scientific records.** Use a shared Python builder, with operation-specific facts supplied by each producer rather than guessed from a generic status string. The image save boundary is `tools/image_workspace.py:953–968`; structure save is `crystallography/structure_tools.py:774–787`. Add the helper's source hash to new-record software provenance if it determines scientific semantics. Do not add fields while reading or restoring old objects.
2. **Keep the three scopes distinct.** Numerical computation/checks; reliability dimensions with assessed/satisfied, assessed/problem, not assessed, or information insufficient; candidate interpretation with actual observations/checks/conditions/conflicts/unresolved alternatives. A valid one-direction measurement can coexist with an insufficient two-direction feature test. Existing original status remains visible and unchanged.
3. **Do not invent candidate explanations in a generic adapter.** Existing discovery review already has observation text, candidate explanations, unresolved questions and bound evidence refs (`image_discovery.py:303–306`). The adapter can accurately describe a fixed finite geometric comparison; free interpretation belongs in existing explicit notes/review records, attributed as supplied and revisable.
4. **Use one bounded Node projection/rendering contract.** Apply it to `publicImageObject`, full domain rendering, crystal root/candidate/side payloads where present, and restore handling. For compact Python summaries retain the root and relevant row field explicitly. Use the same names/status meanings, not separate per-widget interpretations. Ordinary full MCP JSON needs no special transform.
5. **Missing is historical, not failed and not assessed.** Display “not recorded in this saved version” for absence. It is useful UI state, not a newly asserted scientific assessment on the old object. Known versions can be displayed; unknown versions should offer the original record without fabricated eligibility. No writeback, no hash recomputation, no legacy migration by reinterpretation.
6. **Preserve budgets and original requests.** A semantic display projection failure does not revoke a completed saved computation. Refer to the saved object/request; do not replay unknown work. Keep currentness/source/grid/calibration checks orthogonal to all three scientific layers.

## 5. Skills and Agent behavior

The existing scope references support Route A, but they do not enforce API permissions:

- `microscopy-automation/references/peak-quality.md:20–30` distinguishes the numerical FFT proxy, non-SNR local ratio, unknown localization, and per-peak non-certification; one-family feature insufficiency does not invalidate the measured direction. `42–49` gives operations and claim-specific stops.
- `microscopy-automation/references/automation-scope.md:34`, `59`, `64–73`, `86–88` separates candidates/observations/checks; old v1/v2 interpretations are retained; `valid` is not crystal confirmation.
- `microscopy-router/SKILL.md:13` routes via actual current Panel/scientific state without forcing full fields or advanced diagnostics; AnalysisContext is reference-only. Unknown physical calibration allows pixel analysis; unknown requests are queried using the original ID.
- `crystallography-compare/references/general-evidence.md:34`, `48` keeps physical-unit and currentness limitations explicit; `twin-evidence.md:37–43` separates projected/interface/joint statements and controls.
- `microscopy-observe-revise/SKILL.md:42–54` requires valid current anchors and remeasurement after source/calibration changes. That is freshness, not a statistical confidence assertion.

For the new Skill text, require an action record using existing notes/evidence: selected object/ROI/peak → reasons → actual evidence refs → executed tools → resulting observation → unresolved judgments. Allow a working preference when evidence is weak, but never invent SNR, localization errors, calibrated probabilities or a human author. Processing contrasts of one image share source evidence. Lack of one qualification limits the corresponding claim; it does not prohibit all observations or conditional candidates.

## 6. Required regression targets and architectural stop

The following are proposed tests, **NOT_TESTED in this read-only subtask**:

- New-field exact preservation through saved manifest → full MCP → compact root/sample/domain → bounded detail → ordinary/domain/crystal Panel; unknown version, absent field, oversized field and malformed field must not yield new qualifications.
- Legacy object read/result/restore retains original bytes, manifest hashes, request IDs, candidate meanings and physical-claim flags. New metadata must not invalidate historical version validators.
- Single-direction measurement remains observable while a multi-direction feature is insufficient; missing physical calibration retains pixels; raw numerical `valid` is never displayed as verified lattice.
- Multiple compatible candidate structures remain alternatives; missing completed child comparison has no invented matched counts; stale/manual-edited measurements remain unusable for current labels until remeasured.
- Same image under processing contrasts is not independent evidence; explicit Agent manual ROI is not called a researcher statement; annotation `user_confirmed` alone is not actor verification.
- Unknown original side-effect request is queried/recovered, never automatically repeated because a projection or semantic field is unavailable.

**Architecture stop:** do not build a global truth/quality scalar, infer unprovided noise statistics, or rewrite every downstream gate to demand physical certification. Those would change the evidence definition and exceed the additive Route A task. If a shared field requires broad reformatting of immutable records or runtime flows, retain the existing result and present at least two explicit schema/transport options for discussion. The local transfer points identified above make a bounded additive approach plausible; actual integration and runtime verification remain the parent's responsibility.

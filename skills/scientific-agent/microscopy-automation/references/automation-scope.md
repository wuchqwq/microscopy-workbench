# Bounded automation: automate work, not unsupported physical conclusions

This is current **Agent orchestration guidance**, not a changed provider schema,
new numerical gate, probability calibration, or a fix for the open science bugs.
An advertised tool remains callable; do not report a risky path as technically
disabled merely because this Skill says not to choose it automatically.

## Default supported task

Either the researcher opens the GUI first, or the Agent receives an explicitly
accessible original image and opens the shared Panel through the existing tools.
Both routes use the same saved source/frame/ROI/calibration objects and the same
human-edit protection. Agent activation stays host-owned and on demand.

For the bounded first task: inspect one image and a small explicit set of ROIs,
record the question/reason, obtain saved FFTs and inspect peak quality, then
measure projected periodicities/directions. The researcher or Agent may propose
a small set of physically motivated explanations from actual image observations,
saved measurements and the user's material background. Candidates need not all
be supplied by the user or have complete simulations before discussion.
For formal structure-tool comparisons, supply the required sourced structures,
orientation, scale and fixed registration; missing inputs limit that check only.
Return the actual measurements, residuals, unmatched observations, alternatives
and missing premises to the shared Panel. Reuse scientific objects and preserve
old request outcomes. A whole-image field is not a prerequisite.

The Agent can propose ROIs and hypotheses; label them as Agent proposals, not
human selections or confirmed defects. Ask for missing inputs when they affect
physical interpretation. Do not fit the experiment's calibration to a candidate.

Use existing notes, immutable results and evidence references to keep four things
distinct: observed phenomena and sources; candidate explanations and reasons for
proposing them; checks actually executed; and compatible, conflicting,
insufficient or indistinguishable aspects. Do not assign uncalibrated candidate
probabilities. A candidate with no simulation may remain in discussion with its
unperformed checks explicitly marked; do not invent experimental facts for it.

No automatic experimental planning is part of this stage. Do not choose the next
tilt, imaging conditions, experiment sequence or information-value score.
If the current image cannot distinguish candidates, retain the ambiguity and
state why. Do not add a candidate database or general decision framework.

## Explicit exploratory opt-in, not the default route

A full structure field, automatic region proposals, GPA, projected topology,
Sigma3 hypotheses or cross-method scheduling requires an explicit relevant
question, suitable inputs and a stated budget. Do not start these merely because
FFT/ROI analysis is available. Single-domain/reference/carrier assumptions must
be stated; a numerical GPA mask is not independent material-strain evidence.

Occupancy persistence is repaired for new v2 atom snapshots: per-site fractions
survive save/reload/derive, and only full ordered candidate models enter the
current simulation/twin path. This verifies the supplied model, not experimental
chemistry. Legacy snapshots retain their original interpretation and cannot gain
qualification by reloading; explicitly reopen original input for new checks.

Topology v3 checks actual saved direct/conjugate Fourier support before granting
cross-band redundancy. Reused support retains conditional diagnostics with
`redundancy_validated=false`. Historical v1/v2 results retain their old meaning;
create an explicit revision for the new check. Even disjoint supports are not
independent experiments or evidence of a confirmed material defect.

Peak detector v2 refuses unresolved numerical amplitude contrast, including the
reproduced flat-spectrum roundoff peaks. The fixed binary64 depth-based policy
is explicitly not a certified FFT error bound, measured SNR or physical peak
validation. True contrast near floating-point resolution can remain unresolved.
Old unversioned peak objects keep their original interpretation; new automatic
measurements/fields require current detection. Atlas/joint revisions rerun peak
detection on the same saved FFT instead of silently reusing a legacy peak table.
Explicit manual measurement overrides retain their source and caller meaning.
These repairs do not turn `valid` fields into evidence of a crystal or authorize
automatic material interpretation. Inspect support and conflicts; do not invent
thresholds in chat or silently reinterpret old objects.

## Evidence rules in every route

- Distinguish measured geometry, supplied assumptions, simulated candidates and
  independently supported material interpretations.
- Geometry compatible with a finite list is not unique phase identification;
  absence of a predicted reflection is not a universal negative without a
  qualified visibility/detection model.
- Reusing one FFT/peak/window/calibration across modules does not create several
  independent observations. Overlapping ROI windows are not independent by ID.
- Missing calibration, unresolved source, insufficient peak quality or competing
  explanations keep their unknown/insufficient status. A request completed, a
  mask valid, or an immutable record recovered is not a physical-validation PASS.
- Matching tolerances are deterministic criteria, not a 95% confidence level.
- Preserve v1/v2 histories and query failed/unknown original requests. Do not
  rerun them under new IDs just to make a result look successful.

The deliverable answers: which explanations this image supports, what each is
based on, which checks it passed, what conflicts remain, and what the existing
information cannot decide. It does not automatically confirm material structure.
